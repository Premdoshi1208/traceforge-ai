# Five-minute technical walkthrough

1. Open the public landing page. Read the value statement and inspect the interactive seven-responsibility pipeline.
2. Open Mission Control. Inspect stored runs and the current provider, persistence, and verification configuration.
3. Select Broken Orders Deployment and launch a live controlled incident. Capacity limits are explicit; a launch never silently becomes a recording.
4. Watch real events: HTTP failure, selected tools, source evidence, competing hypotheses, original reproduction, proposed source, isolated verification, review, and report. Groq resets or GitHub queues may extend the run.
5. Open Repair Studio. Compare original/generated code and Git diff. Inspect the original nonzero test result, patched and regression exit codes, execution mode, job link, and residual risks.
6. Download the incident report and patch. Generated patches are review artifacts; they are never deployed automatically.
7. Open Incident Intelligence to inspect unsuccessful attempts and real completed runs without consuming inference quota. Recorded examples are labeled and retain run IDs/timestamps.
8. Inspect Evaluation Arena and Architecture. Engineering test outcomes are distinguished from model judgments and actual live-run counts.

A live run can legitimately stop without a safe fix or available verification. That is an honest result. For interviews, keep one actually verified completed run available alongside the live launch.
